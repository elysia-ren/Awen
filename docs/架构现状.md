# Awen 编辑器架构现状(2026-10-02 修复后)

> 本文档梳理同步/性能修复全部落地后的真实架构。
> 数据流、副本链、守卫体系、调用层级、已知边界,全部以代码为准。

---

## 1. 数据权威与副本链

### 权威(唯一)

```
User Syntax 明文 —— 运行时持有点: gSrc(前端全局变量)
                     持久化形态:   .awen 容器内明文 chunk
```

改文档 = 只改 `gSrc`。所有其他形态都是它的投影或缓存。

### 派生状态清单(分四层,全部单向写入)

```
gSrc(权威)
 ├─ 投影层
 │   ├─ textarea.value   语法视图直显        [taSafeWrite;程序写持 writeToken]
 │   ├─ 纸面 DOM         引擎渲染投影        [renderNodes 全量 / replaceSegBlock 差分]
 │   └─ gSegCache        段缓存(文本+span)   [每次渲染后重建]
 ├─ 请求缓存层
 │   └─ PARSE_CACHE      (src,cfg,rev)→响应  [size-1,新请求逐出]
 ├─ 增量历史层(引擎持有,按文档隔离+revision 界定)
 │   └─ g_states[].psrc/plex/flow/prev_rev  [relayout 后更新;rev 跳变即作废基线]
 └─ 引擎运行层(无文档语义)
     └─ DLL @global 两段输出缓冲             [每次调用覆写;DLL_CALL_LOCK 串行]
```

**不变量:派生状态允许暂时落后,但永不被旁路修改,且每份有明确失效规则。**
②纸面是唯一例外(contentEditable),靠守卫体系兜住,根治=浮层方案(§7)。

## 2. 引擎三级调用链

```
前端 invoke
   ↓
① dll_call        awen_pipeline.dll(C 转译,带宽表/几何全参)
   │  parse: 3ms(小)~300ms(85KB)   relayout: 同级
   │  守卫: op=parse/relayout;DLL_CALL_LOCK 互斥
   ↓ 未命中/失败
② inproc_call     常驻 Interp 解释 daemon_handle(512MB 栈 worker)
   │  全功能(parse/relayout/parse_blocks/pack/unpack)
   │  @global g_states 按文档隔离,增量排版跨请求复用
   ↓ 加载失败/超时
③ spawn daemon    aine.exe run tauri_cli.aine(行为兜底,锁覆盖读写)
```

- `parse_blocks`(段级增量,~20ms)只有 ②③ 有;DLL 未导出(单段解析走 inproc 足够快)
- 守卫链:`dll_call` Err → `inproc_call` Err → spawn;每级 eprintln 降级原因

## 3. 渲染路径(三条,按编辑来源分派)

### A. 语法侧编辑(主路径,syntaxIncrRender)
```
textarea input →(30ms 防抖)→ applySyncNow
  → gSrc = ta.value(语法侧即权威)
  → syntaxIncrRender(gSrc):
      行级 diff(gSegCache 对比)→ 脏段集
      ├─ 无脏段 → return(幂等)
      ├─ span 错位/节点数/kind 变 → render() 全量(结构编辑安全网)
      └─ 脏段 → Bridge.parse_blocks(②级,~20ms)
                → 校验(count/kind 不变)→ replaceSegBlock 原位替换
                → obj 块补绑 click / bid 回填 / outline+status 刷新
```

### B. 纸面侧编辑
```
paper input →(30ms 防抖)→ applySyncNow
  → patchSource(最小源补丁,只替换变化段;结构断裂回退 serializeAll)
  → gSrc 推进 → scheduleNativeRefresh(300ms)
  → incrRefresh: DOM 序列化 vs gSegCache 比对 → 脏段
      ├─ 无脏段 → true(完成)
      ├─ lastRenderedSrc !== gSrc → false → render() 让位
      └─ 脏段 → parse_blocks → 原位替换(同 A 校验)
```

### C. 全量 render(renderNodes)
```
render(src) → renderSeq++;docAtReq 快照
  → parseSafe(①级,data URI 剥离)→ 响应落地:
      过期检查(seq/docId)→ 守卫期?(见 §4)
      ├─ 差分可命中(块数/kind/recs 对齐)→ 只 replaceSegBlock 变化块
      └─ 否则 → ingestNative → layoutFromEngine → renderNodes 整版重建
  → applyDocsets / outline / status / gutter / 横向 setPage
```

**排版自愈**:编辑停 800ms → applyRelayout(relayoutSeq 令牌)
→ 引擎增量排版(psrc 基线+脏区重扫)→ 页分配变化才重建。

## 4. 守卫体系(时序/会话/并发)

| 守卫 | 保护对象 | 机制 |
|---|---|---|
### 一致性核心(2026-10-02 重构后:单一判定取代多令牌)

| 机制 | 说明 |
|---|---|
| **`sourceRevision`** | 每次权威写入(commitSource)+1;所有异步任务携带 (doc, rev) 快照 |
| **`isCurrent(job)`** | 所有引擎响应落地前统一判定:doc 变或 rev 变 → 丢弃 |
| `lastRenderedSrc` | 语义=投影已落地到的 **rev**(数值);字符串比对已废除 |
| `writeToken` | 程序写 textarea 的确定性识别(替代 800ms 时间窗猜测) |

### 输入/会话层(体验保护,非正确性依据)

| 守卫 | 保护对象 | 机制 |
| `lastPaperInputAt` 800ms | 纸面打字会话 | 守卫期内不重建纸面(纸面为准) |
| `window.composing` | IME 组词 | 组合期不序列化;compositionend 后 50ms flush |
| 800ms 会话窗 | 语法/纸面打字中不重建 | writeToken 为主,时间窗仅兜边角 |
| `renderPending` | 旧内容覆盖 | 在途时 applySyncNow 推迟 |
| `DLL_CALL_LOCK` | DLL 全局槽竞争 | 整调用互斥 |
| `emptyParaUnderCaret` | 空段光标(编辑器行为保真) | 推迟重建+补跑(isCurrent 校验) |

引擎侧:`g_states` 增量基线带 `prev_rev`——请求 rev 与基线不连续
=中间有提交未经过引擎 → 基线作废,该次 relayout 自动全量。

## 5. 性能现状(实测,2026-10-02)

| 场景 | 延迟 | 路径 |
|---|---|---|
| 小文档(3 行)语法侧打字→纸面 | **81ms** | A(30 防抖+parse_blocks+原位替换) |
| 85KB 文档段中打字→纸面 | **127ms** | A |
| 85KB 文档结构追加 | ~550ms | A→C 回退(全量) |
| 首次打开 85KB → 渲染完成 | ~700ms | C |
| relayout(停 800ms 后) | ~370ms | ①级 DLL |
| Ctrl+A 跨页全选+Delete | 即时 | 程序性 deleteContents+光标复位 |

引擎侧:parse ①级 3ms(小)/300ms(85KB,DLL 摊销后);②级约 ×3;
③级秒级(仅兜底)。

## 6. 已知边界(未修/受限于结构)

1. **纸面侧 contentEditable 仍是"第二编辑源"**——守卫体系兜住了已知路径,
   但浏览器自主编辑行为(拖放、右键粘贴、语音输入等)仍可能绕过,
   每个新入口都需逐一接管。根治 = 浮层方案(纸面纯渲染,§7)。
2. 结构编辑(Enter 拆段/合并)走全量 render,85KB ~550ms——可接受,
   浮层方案后 Enter 由我们直接翻译源码,不受此限。
3. DLL 未导出 parse_blocks/增量排版(单段 20ms 走 inproc,暂无必要)。
4. IME 组词期间纸面不实时(组合态不进 gSrc 是设计,组词完成即 flush)。
5. 并发开两个 .awen 容器:unpack 落地路径仍固定(低概率,待唯一化)。

## 7. 下一步方向(已论证待批)

**浮层编辑方案**(纸面纯渲染 + 行内浮层直改 gSrc):
- 消灭 §6.1 的全部旁路;六副本全部单向写入
- 编辑与语法视图完全同链路(那条链路零 bug 史)
- 工作量 3-5 天;用户体验不变(光标/打字/IME 显示效果一致)

其余候选:relayout 增量进 DLL、占位功能落地(60 处)。
