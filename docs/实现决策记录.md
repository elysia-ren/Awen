# Awen 实现决策记录(设计偏离与边界确认)

> 2026-09-21。对照《原型设计方案.md》《开发计划.md》逐项确认后的决策记录。
> 性质:承认实现与设计的偏离,锁定决策,避免反复。每条含理由与影响。

## D-R1 撤销/重做走前端 hist,不接引擎 undo.aine(E1-5 偏离)

**决策**:保留前端 hist 数组(语义步:500ms 窗口合并+标点成步+基线入栈),不把
undo.aine 双栈接入编辑链路。

**理由**:撤销必须与 DOM 光标恢复、跨页渲染联动,引擎双栈面向"源码 patch"模型;
接入需要 patch↔DOM 双向同步层,复杂度高于收益。引擎 undo.aine 保留(测试全绿),
作为未来"语义编辑 API"的组成部分。

**影响**:§4.4 合并规则由前端语义步等价实现;跨文件切换时撤销栈重置(文件隔离)。

## D-R2 选区映射(inline_span_map)不接入当前 UI(E2-1 偏离)

**决策**:纸面编辑走"DOM 序列化回写"路径(serializeAll);inline_span.aine 的
选区↔源码区间映射能力保留为引擎 API,不在 WYSIWYG 视图接入。

**理由**:DOM 回写已支撑全部当前编辑场景(粗斜/颜色/表格/作用域回写);
选区映射的价值在"源码视图高亮同步",列为语法视图增强的候选,非必需路径。

**影响**:E2-1 的验收(选区映射正确)由序列化往返一致性测试等价覆盖。

## D-R3 分页一致性:以前端像素实测为准(E3-1/E3-4 决策)

> **【已取代 v1.2.0(3d896a8)】** 本决策与当前实现相反,现行决策见 D-R7。

**决策(已废弃)**:分页结果的权威是**前端像素级实测分页**(DOM 真实字体测量);
引擎 page_flow(均匀宽度模型)作为排版算法基线保留。导出/打印以前端 DOM 快照为准。

## D-R7 分页权威归引擎:A′ 单一排版权威(v1.2.0 取代 D-R3)

**决策**:分页与断行的唯一权威是 **Aine page_flow**;前端第二套排版引擎
(breakLines/measureEm/tokenize/layoutPages)已整体删除,前端只按引擎下发的
recs 页号把**整块**落到对应页(不劈段)。daemon `op=parse` 携带 cfg 同一次解析
附带权威分页(`pages`+`recs`,零额外往返);docsets 结构化下发(任意语言别名
在引擎归一为英文规范键),前端不再按命令词猜。

**理由**:两套排版引擎必然漂移(GPT 评审债③);估宽与真实字形的偏差表现为
分页点略不同,但纸面/分页符/页码从此同源,内部永远自洽。

**取舍**:分页精度为 em 估宽级(印刷级 shaping/glyph metrics 是后续课题);
超长段整块落页不劈段(见 D-R8);增量编辑期间分页不重算(见 D-R9)。

**影响**:README"像素级分页"表述已改为"引擎分页";引擎 `fast` 估行模式
(v1.4.1)服务 daemon 交互路径,精确断行仍用于导出/增量收敛。

## D-R4 增量解析/布局:暂不接入(E3-4/E6)

> **【部分取代 v1.2.0(3d896a8)/v1.4.0】** 块级增量解析已接入编辑器实际
> 工作路径;增量布局仍未接入(现行取舍见 D-R9)。

**决策(部分废弃)**:行级增量(lex_incremental)与增量布局(page_flow_incremental)
保留在引擎并维持测试,编辑器暂不接入,继续全量解析+像素重排。

## D-R8 超长段整块落页,不劈段(v1.1.1)

**决策**:超过一页容量的段落**整段独占一页**(纸面纵向溢出承接),
layoutPages 时代的按显示行劈段机制废弃(其 DOM 切片会使序列化静默丢失
页外内容——打开即丢,无需编辑)。

**影响**:分页结构正确性优先于超长块的分页观感;劈段相关代码
(l0/l1/partLines)保留为防御性死路。

## D-R9 增量解析与增量布局解耦(v1.2.0 起的现行取舍)

**决策**:输入暂停后的刷新路径=**块级增量解析**(脏段经 daemon
`op=parse_blocks` 独立走权威管线)+ DOM 原位替换;**分页不重算**——
页数变化待下次全量刷新(打开/撤销/结构变化/语法侧编辑)自然修正。

**理由**:增量排版需要引擎/前端双向页状态同步,复杂度高;
文本级编辑的页数漂移是渐进且可见可接受的,纸面(用户工作面)不受影响。

**影响**:当前"真增量"=增量解析+增量 DOM 更新,**非增量排版**;
GPT 评审对 Incremental Layout 评分 35-40%。page_flow_incremental
(sigs 稳定点收敛)在引擎已具备,接入是后续增量排版的入口。

## D-R11 版面签名覆盖样式属性 + 增量排版页内精确恢复(v1.16.0)

**决策**:page_node_sig 升级为版面级签名——行内部分用专用
page_inline_sig(保留 Scoped 命令名与 RawInline/Command 参数,
区别于测宽用的 inline_marked_text),obj 节点纳入全部 args/attrs
(图片 width/align 改变即签名改变);NodeBox 增 start_y 字段,
增量排版恢复点从"页首 y=0"升级为"上一轮该节点的页内精确位置"。

**理由**(GPT 三审指出的 P0):纯文本相同的节点字号/字体不同则
版面完全不同,旧签名导致样式类编辑不触发增量重排;仅知页号不知
页内 y 的恢复是"页级增量"而非"layout-state 增量传播"。

**影响**:增量排版等价性有专项测试(incremental_fast_matches_full:
增量结果与全量逐盒等价);para-spacing 的 em 换算跟随实际字号
(doc_para_spacing_mm 参数化,不再固定 11pt)。

## D-R12 daemon 增量排版状态按文档隔离(v1.16.0)

**决策**:daemon_loop 持有 Vec<DaemonLayoutState>(doc 键控),
替代全局单槽;宽表一致性比对升级为 s(区间首字符)+k(宽度指纹,
前端下发)双比对。

**理由**:多标签场景下全局单槽会被最后一个活跃文档覆盖,切换标签
后增量退化全量(签名兜底保证正确性,但失去增量收益);宽表只比
wf_s 不比宽度数组,"看起来相同"不等于度量相同。

## D-R10 docx 导入:导入即资源化 + 矢量图占位(v1.4.1)

**决策**:docx 图片在导入时批量资源化进媒体目录(`core_batch_resource`
一次 IPC+内容哈希去重),源码只留 media/ 引用;wmf/emf(浏览器不支持的
公式/矢量格式)在 HTML 层占位化并计数明示,不转 data URI。

**理由**:20MB 化学卷实测 2228 图全转 data URI 时源码膨胀至 24.6MB,
解析/渲染/保存全链路被压死;批量资源化后源码 112KB。

## D-R5 多行作用域 @[font/size/color] 引擎侧未支持(已知分歧)

**决策**:预览引擎(ingestNative 之前)支持多行作用域块的解析/渲染/序列化;
Aine 原生解析器暂不识别(按 docset+段落处理)。桌面版通过"引擎分歧"警告暴露。

**影响**:含多行作用域的文档在桌面版打开时块结构来自原生(语义降级);
待规范确认作用域的块级语义后在 parser.aine 补齐。

## D-R6 表格 widths 列宽为编辑器扩展

**决策**:`@[table 名 widths: 30,40,30]` 参数由前端实现(colgroup 渲染+回写),
不进入 Awen 核心规范;native 解析器视 table 开行为不透明行,不冲突。

**影响**:该参数在纯 CLI 排版路径无效果;晋升为规范需先冻结语法。
